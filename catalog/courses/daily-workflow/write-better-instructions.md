# Write better instructions

_Stub article._ Outline only — full draft later.

**Audience:** Individual developers  
**Sources:** [Good vs. Bad Instructions](https://docs.openhands.dev/openhands/usage/essential-guidelines/good-vs-bad-instructions) · [Prompting Best Practices](https://docs.openhands.dev/openhands/usage/tips/prompting-best-practices) · [When to Use OpenHands](https://docs.openhands.dev/openhands/usage/essential-guidelines/when-to-use-openhands)

## What this lesson covers

- Ask for the outcome, not the exact commands
- Add constraints: files, tests, style, what not to touch
- Give the agent a way to know it is done
- When a task is too large and should be split

## Outline

1. Outcome, context, constraints
2. Examples of weak vs useful prompts
3. Ask for tests and a short summary of changes
4. Stop and redirect if the agent drifts

## Try this

Rewrite one of your last prompts as: goal, files in scope, and how you will review the result. Send both versions on a throwaway branch and compare the diffs.
