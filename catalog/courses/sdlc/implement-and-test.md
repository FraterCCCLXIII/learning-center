# Implement, test, and document

_Stub article._ Outline only — full draft later.

**Audience:** Individual developers and teams  
**Sources:** [OpenHands in Your SDLC](https://docs.openhands.dev/openhands/usage/essential-guidelines/sdlc-integration) · [Automated QA Testing](https://docs.openhands.dev/openhands/usage/use-cases/qa-changes)

## What this lesson covers

- Feature implementation against existing patterns
- Bug fixes with regression tests
- Coverage goals and test factories
- Docs written in the same conversation as the code

## Outline

1. Implement from a spec, not a vague ask
2. Generate tests and re-run until they pass
3. QA that runs the software, not only reads the diff
4. Update docs when the public surface changes

## Try this

Pick a module under 80% coverage. Ask the agent to raise coverage with tests that fail first if they are wrong — then fix code or tests until green.
